When a prompt “works” on your examples

You revise a prompt until it gets every development example right, then try it on new cases. Some of the revisions were genuine improvements; some just happened to suit those particular examples. The held-out test shows which.

What to notice

With the defaults, about four projects in five reach a perfect development score. Yet the chosen prompt’s true accuracy is barely above that of a typical variant (about 0.86 against 0.85): selecting on 20 examples mostly selects luck. The test score centres on the truth, but with 40 cases it wanders by about ±11 points (Math Box 136.1: 34/40 = 0.85, interval about 0.74–0.96).

Increase the development set and a perfect score becomes rarer and more meaningful. Increase the test set and the estimate tightens — telling 85% from 90% needs several hundred cases. The discipline is the same as for any model: a test set that played no part in choosing, and an honest interval around what it says (Chapters 19, 27, 136).
