Why generating text is limited by memory, not arithmetic

To produce each new token, the accelerator must read every model weight from memory — but does only about one multiply-add per weight read. Memory bandwidth, not arithmetic, sets the speed limit for a single conversation. Batching many users together changes the picture.

What to notice

7B in 16 bits is 13.5 GB; at 2 TB/s one read takes about 6.7 ms, a ceiling of about 150 tokens per second for one user, even though the arithmetic could allow thousands (Math Box 88.1).

Quantize to 4 bits and single-user speed roughly quadruples. Add users and each weight read serves them all, so total throughput rises almost in proportion — until the green line hits the compute limit. That is why providers batch, why local models are quantized, and why prefill (all prompt tokens at once) is compute-bound while decoding is memory-bound (Chapters 88, 100, 105).
