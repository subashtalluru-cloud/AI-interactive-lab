Tracing a retrieval-augmented answer — and breaking it

A question is scored against a small library of guideline chunks; the best few are pasted into the prompt the language model will see. Everything the model can ground its answer in is decided here, before it writes a word. Then introduce the four classic failures and watch what reaches the prompt.

The library is a short invented teaching text, not real guidance. Scoring here uses word overlap weighted by rarity (TF-IDF cosine) so every number can be followed by hand; production systems use learned embeddings, often combined with keyword scores.

What to notice

The answer can only be as good as the chunks that reach the prompt. The outdated document scores well because it uses the same words; the near-miss chunk looks relevant but concerns a different population; the split sentence leaves the number in one chunk and its meaning in another; the planted instruction arrives inside “evidence”.

None of these is fixed by a stronger language model. They are fixed upstream: dates and versions as metadata, chunking along meaning, re-ranking, filtering sources, and treating retrieved text as data rather than instructions (Chapters 127 and 156). Retrieval quality multiplies with answer quality — 0.9 × 0.9 caps the whole system near 0.81.
